# The autonomous editing engine (V4)

`xoxo edit --assets <folder> --type <type> --prompt "..." --output <folder>` takes a folder of media and a plain-English
brief and produces a finished, verified edit. Nothing in your folder is modified, executed or deleted.

```
xoxo edit --assets "D:\Projects\J20\INPUT" --type velocity \
          --prompt "aggressive J20 stealth fighter edit, military look, 30 seconds" --output "D:\Projects\J20\OUTPUT"
```

## What happens, in order

| Step | Module | Output |
|------|--------|--------|
| Read the brief | `src/director/prompt.js`, `config.js` | edit type + 15 behaviour dials, with *where each came from* (`plan.directive.sources`) |
| Scan + understand the media | `src/assets/*` | `assets.manifest.json`, per-asset visual analysis (brightness, colour, subject box, motion, perceptual hash), cached by file fingerprint |
| Universal library | `src/library/*` | SFX / music / overlays indexed with tags, energy, intensity, features measured from the audio itself ([LIBRARY.md](LIBRARY.md)) |
| Music + beats | `src/director/music.js`, `src/beat/*` | the user's music first, else the best library track; `beat_map.json` ([BEATS.md](BEATS.md)) |
| Direct | `src/director/direct.js` | `plan.json` (timeline mode) + `DIRECTOR_REPORT.json` ([TIMELINE_PLAN.md](TIMELINE_PLAN.md)) |
| Critique + refine | `src/creative-qa/*` | `CREATIVE_QA.json`; best of several cuts ([CREATIVE_QA.md](CREATIVE_QA.md)) |
| Build | `src/ae/compile-timeline.js` + executor | the After Effects project, incrementally ([ARCHITECTURE.md](ARCHITECTURE.md)) |
| QA + repair | `src/qa/*` | `QA_REPORT.json` (8 checks) |
| Render + render-level QA | `src/render/*`, `src/creative-qa/render-checks.js` | the video, verified with ffprobe, then inspected for black frames, freezes, bars, clipping, silence |
| Report | `src/app/produce.js` | `EDIT_REPORT.md`: decisions, dials, shots, fallbacks, **what was not verified** |

## The pieces

* **Edit types** ([EDIT_TYPES.md](EDIT_TYPES.md)) — 23 behaviour profiles, not templates.
* **Velocity** ([VELOCITY.md](VELOCITY.md)) — speed maps integrated to a source position, sampled into time-remap keys; ramps that land exactly on a beat.
* **Motion + camera** ([MOTION_AND_CAMERA.md](MOTION_AND_CAMERA.md)) — 14 composable primitives, 5 camera rigs, crop-based 2.5D, guaranteed edge coverage.
* **Shots, transitions, type, colour** ([SHOT_TEMPLATES.md](SHOT_TEMPLATES.md), [EFFECTS.md](EFFECTS.md)) — every technique is an effect id with a fallback chain whose last link needs nothing.
* **Sound** — semantic SFX search (never random) and a smart fit that puts the sound's transient on the visual event.
* **Tiers** — `--quality draft|preview|final` are separate projects; `xoxo promote` re-uses an approved plan at full resolution.
* **Memory** — optional, local, ids and ratings only (`xoxo memory`).
* **Benchmarks** ([BENCHMARKS.md](BENCHMARKS.md)) — four professional briefs with machine-checked checklists.

## Commands

```
xoxo edit --assets DIR --type T --prompt "…" [--output DIR] [--quality draft|preview|final] [--duration S] [--seed N]
          [--professional] [--music auto|off|FILE] [--config edit.config.json] [--set velocity=0.8,camera=0.4]
          [--starter-sfx] [--dry-run] [--no-render]
xoxo direct [project] [--seed N --type T --prompt "…"]     re-run only the Director
xoxo beats AUDIO [--out beat_map.json]                       analyse any track
xoxo library init|scan|starter|search "fast transition"      the universal library
xoxo critique [project] [--render FILE | --last]             creative QA
xoxo promote PROJECT --to final|preview|draft                 re-use an approved cut at another resolution
xoxo memory show|reset|like ID|dislike ID                     local taste memory
xoxo benchmark velocity|cinematic|documentary|commercial|all [--dry-run]
```
Every command takes `--json`. The MCP server exposes the same capabilities as `xoxo_produce`, `xoxo_direct`,
`xoxo_beats`, `xoxo_library_search`, `xoxo_critique`, `xoxo_promote`, `xoxo_memory`, `xoxo_benchmark`.

## edit.config.json

Found next to the assets, one folder up, or in the repo root (or `--config FILE`). For plain values (`type`, `duration`,
`seed`, `resolution`, `music` …) a CLI flag replaces the file's value. For the behaviour **dials** the order, lowest to
highest, is: edit-type defaults → `intensity` → `overrides` in the file → the words of the prompt → explicit overrides
(`--set velocity=0.8,camera=0.4`, or `overrides` in the MCP tool). Every dial records its source in `plan.directive.sources`.

```json
{ "type": "velocity", "style": "military", "intensity": 0.9, "duration": 30, "seed": 7, "resolution": "4k",
  "music": "auto", "sfx": "auto", "captions": false, "professional": false, "memory": true,
  "title": "J20 STEALTH", "overrides": { "transitions": 0.2, "beatSync": 0.95 } }
```
Unknown keys produce warnings; wrong values are errors with the allowed range. `--set` is the **human override**: applied
last and recorded as `override`. You can also hand-edit `plan.json` — it is the source of truth — and run
`xoxo edit <project>`; builds are incremental and idempotent. To change just the cut, `xoxo direct <project> --seed 12`.

## Professional mode

`--professional` (or `"professional": true`) is restraint: no glitch, distortion or kinetic type, no shake, more hard cuts,
longer shots, fewer simultaneous effects, softer dials. Use it for brand work.

## Safety

Source media is read-only; assets are untrusted data; nothing is downloaded, installed or executed on the way (the starter
sound pack is *generated* with FFmpeg, offline). Raw ExtendScript stays disabled. See [SECURITY.md](../SECURITY.md).

## What is verified, and how

| Layer | Evidence |
|-------|----------|
| Prompt/config → directive, beat engine, velocity maths, motion primitives, camera tracks (edge coverage fuzzed), transitions/typography/compositing planners, SFX search + fit, Director, creative QA, tiers, memory | Automated tests; deterministic; real FFmpeg media where audio/video is involved |
| Every op the compiler emits | Executed through the **real host scripts** inside the simulator (`src/bridge/mock-ae.js`): argument names, idempotency, layer names, timing, time-remap keys, masks, z-order |
| Render-level creative QA | Tested on FFmpeg-generated clips with planted defects |
| **Behaviour inside real After Effects** — `time_remap`, track mattes, text animator `Based On = Words`, `Directional Blur` / `CC Radial Fast Blur` / `Wave Warp` / `Gradient Ramp` / `Exposure` / `Hue-Saturation` / `Brightness & Contrast` parameter names, `layers_reorder` with hundreds of layers, 4K performance | **Not verified.** Written against the documented API; every use has a fallback. `xoxo benchmark velocity` (without `--dry-run`) on a machine with After Effects is the test that settles it. |
| Whether the result is *good* | Not automatable. Creative QA judges structure; look at the preview. |
